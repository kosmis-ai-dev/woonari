# CR-001 / T-006: 평생운세·재물운 원본 계약

구현: `app/legacy_life_wealth.py`. `decide_life_wealth(kind, request, saju)`에 해당 페이지가 포함하는 `function/dotong_function.asp`의 CalcSaju 프로필로 산출한 사주를 전달한다. 특히 23:30 이후 시주는 `dno+1`을 사용하는 프로필이어야 한다.

## 평생운세

원본은 `old/unse/lifeluck/main_end.asp`이다. DB는 전부 결과 문구 조회에 쓰이며 아래 선택키는 Python에서 확정한다.

| 원본 위치 | 판정 | 문구 선택/출력 |
|---|---|---|
| 150~152, helper1319~1366 | 월지·일간으로 십격 결정 | `sipkyuk_code` |
| 162~191 | 십격별 사회/재물/직장/적성 행 조회 | 실제 출력은 `social.desc1~5`, `money.desc1~2` |
| 198~205 | 일주 | `tbSaju_private.hname` → desc1 가치관/desc2 성품/desc3 어드바이스 |
| 211~233, helper1411~1451 | 연지 당사주, 연지→월지, 월지→일지 순서 차이 | `tbSaju_dangsaju.dang_code` → desc1 초년/desc2 중년/desc3 말년 |

실제 표시되는 13개 문구마다 독립된 `selectors` 항목을 만든다. 원본 쿼리의 행 필터와 열 선택을 보존하면서 한 쿼리를 출력 슬롯별 계약으로 나눈 것이다. `jikjang`/`job`은 조회되지만 이 페이지에 출력되지 않아 AI 슬롯에 포함하지 않는다. 원본의 문구를 읽거나 재작성하지 않는다.

### 대운 제외 이유

459~626의 `daeun` 함수는 `in_ypillar`, `in_mpillar`, `my_minute`를 참조하지만 해당 파일과 포함 helper에는 할당이 없다. 실제 대운 출력표는 812~859에서 HTML 주석으로 가려져 있다. 공개된 출력항목이 아니므로 새로운 라이브러리 대운으로 채우지 않고 `excluded_non_narrative`에 이유를 남겼다. 이 제외는 원본의 실제 평생운세 텍스트 출력 13개를 차단하지 않는다.

## 재물운

원본 `old/unse/moneyluck/main_end.asp`1364~1418은 각 출생 사주 기둥과 일간으로 4개의 문구를 선택한다. 기준일의 일일 점수는 사용하지 않는다.

| 슬롯 | yukgap | daygan | 출력 |
|---|---|---|---|
| wealth-year | 년주 | 일간 | Moneyluck.Money → myCho 초년 |
| wealth-month | 월주 | 일간 | Moneyluck.Money → myJang 장년 |
| wealth-day | 일주 | 일간 | Moneyluck.Money → myJung 중년 |
| wealth-hour | 시주 | 일간 | Moneyluck.Money → myMal 말년 |

성별은 문구 키에 들어가지 않는다. 도깨비 번호 표시의 M/F 접두어만 보존했다.

2636~2721의 인라인 출력 분기(일간 오행 색과 일간이 극하는 재물 오행 색)도 `rendered_inline`에 보존했다. 예를 들어 甲/乙은 목·청, 재물 오행은 토·황이며, 寅/卯와 같은 지지 오행을 새 판정 기준으로 바꾸지 않는다. 그래프의 해당 재물 오행 가중치도 함께 제공한다. 원본에서 정량 기준 없이 “많으면”이라고만 쓴 비겁/인성 설명을 새 임계값 판단으로 만들지는 않는다.

## 공통 사주표·오기·신살

두 페이지가 동일하게 사용하는 helper244~1044의 오행/12운성/공망/합형충파해/신살을 계산 근거로 보존했다.

- `twelveChart`의 2006년 개정 점수: 태40, 양50, 장생90, 목욕30, 관대80, 건록80, 제왕100, 쇠60, 병50, 사/묘/절10.
- 지지의 단계는 일간 기준, 년월시 천간의 단계는 해당 기둥 자체 천간·지지 기준이며 0.5배. 일간 자체 기운은 60점이다. 단순 8자 개수로 대체하지 않는다.
- 원본 그래프의 정규화 인자 `defValue=max(1,maxKi/100)`를 제공한다.
- 원본 `Hyung`의 자형 판단은 첫 해당 글자부터 2글자를 전역 `Replace`한다. 일반적인 중복 개수 판단으로 고치지 않았다.
- 시주 신살의 고신/과숙은 원본 호출 그대로 **연지와 일지**를 비교한다. 시지로 임의 수정하지 않았다.
- 반환된 신살·합형충파해 문자열은 원본 순서와 공백을 보존한다.

## 검증 범위

`tests/test_legacy_t_006.py`는 ASP의 십격120개 명시적 case, 당사주 순서/순환, 실제 표시13슬롯, 재물4슬롯, 가중오기 수치, 신살의 원본 인수 및 자형 Replace 동작을 검사한다. 원본 `manse` 데이터와 ASP 서버를 실행한 결과 대조는 아직 없으며, 독립 만세력 대체의 동일성을 주장하지 않는다.
