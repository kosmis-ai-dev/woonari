# 비회원 un 자료 전체 복원

CR-015 · 2026-11-19. 백업의 121개 테이블을 전수 분류해 un 정의·판정·사전 자료 **78개, 778열, 100,929행**을 MySQL `woonari`에 복원했다. 회원·상담·결제·연락처·세션·로그·개인 신청 기록 등 43개 표는 이관하지 않았다.

데이터가 있는 표는 42개이며 36개는 원본부터 빈 표다. 빈 표도 스키마와 출처를 보존한다. 기존 서비스의 `tb_manse` 73,414행과 앞서 적재한 연간·월별 표는 유지한다. 백업의 과거 만세력 47,846행은 별도 보관 표에만 복원한다.

## 복원 방식

```sh
./woonari db sync-fortune-data .local/woonari/restore/cr015/exports
```

실제 표 이름은 `woonari_source_…`, 출처 표는 `woonari_source_metadata`다. 원본 표·열·형식·NULL·원본 기본 키·행 순서의 출처·파일/데이터 해시는 `python_api/app/data/fortune_archive_registry.json`에 기록한다. 공개 레지스트리에는 행의 실제 값이 없다. 원문·백업·검증 결과·접속정보는 `.local/woonari/`에만 보관한다.

고정된 허용 목록과 추출본 전체를 검증한 후 전용 DB에 연결한다. 문자열·날짜·정수·실수·정밀 수치·NULL을 정해진 형식으로 보존하고, 기존 만세력과 이름이 충돌하지 않는 신규 표만 만든다. DDL 다음 단일 데이터 트랜잭션에서 전체 행을 적재하고 다시 읽어 해시를 대조한다. 같은 자료 재실행은 `already_present`, 다른 자료는 기존 값을 보존하고 중단한다. 원본의 정렬되지 않은 자료에 부여한 `_woonari_row`는 보관 순서이며 ASP 조회 순서로 간주하지 않는다.

전체 허용 열과 표준 자료에 대해 이메일·전화번호·인증값·AWS 키·주민번호 패턴을 검사했다. 제외된 개인 테이블의 행은 읽거나 배포하지 않았다.

## API와 실제 연결

[Swagger](http://127.0.0.1:9090/docs)의 **시작 안내 → 회원 제외 · un 전체 복원 자료와 연결 상태**에서 확인한다.

- `GET /v1/source-data`: 실제 MySQL 출처·행 수·원본 조회 연결 상태
- `GET /v1/un-services`: 서비스별 `source_archive`에 필요한 표, 확보 행 수, 매핑 상태 표시
- `GET /v1/restored-data?year=2027`: 연간 자료의 빈 초기 행과 미확정 규칙 상세

목록에 있는 표의 존재와 개인별 계산 완료는 구분한다. 상태 조회는 AI를 호출하지 않으며 원문·개인정보·접속정보를 반환하지 않는다. 원본 연결이 설정되지 않은 실행은 `not_connected`, 출처 검증 실패는 `unavailable`로 안내한다.

원본 ASP의 조회 키·열 대응을 확인한 자료부터 연결한다.

| 서비스 | 원본 표 | 적용 범위 |
|---|---|---|
| 평생사주 | `TB_Saju_Private`, `TB_Saju_DangSaju`, `TB_Saju_OtherUnse` | 일주·당사주 문자·십격과 social/money 키의 실제 원문 |
| 도통 전생록 | `tbPreLife` | 원본 연·음력 월·일 조회 키, 별도 flag 4 자료는 자동 사용하지 않음 |
| 탄생화 | `TB_FlowerLuck` | 양력 월·일 366개와 꽃 이름·꽃말·원산지·원문 |
| 탄생석 | `TB_birthStoneLuck` | 양력 월 1~12와 보석 이름·상징·원문 |
| 탄생일 | `TB_birthDayLuck` | 월·일 본문. 별도 사건·인물 표가 없어 전체 서비스는 자료 대기 |

연결한 표는 실제 원문까지 해시로 검증해 메모리에 보관하고 조회된 행이 그 원본과 같은지 비교한다. AI에는 해당 출력항목의 검증된 표준 원문만 근거로 전달한다. 실제 전생·가족관계·미래를 확인한 사실로 단정하지 않고 전통적인 상징 풀이로 문장화한다. 수명·질병·사망 등의 민감한 확정 표현은 일반 조언으로 제한한다.

현재 Claude 경로는 항목 ID·본문·필수 근거를 먼저 검증한 뒤 표시 제목을 Python 계약에 맞춘다. 모델이 고정 제목을 다르게 표현해도 계산 항목명은 바뀌지 않는다. 누락·중복·알 수 없는 항목이나 잘못된 근거를 보완하지 않으며, 모델에는 해당 요청에 허용된 항목·근거만 출력 형식으로 안내한다.

원본 `NULL`은 임의 값으로 채우지 않는다. 일부 탄생화의 분류, 전생의 부모 항목이 비어 있으면 비어 있다는 사실을 유지한다. `~symCodeNN~`은 확인한 ASCII 공백·문장부호에 한해 출력용으로 변환하고 HTML을 정리한다. 원본 DB의 값과 해시는 바꾸지 않으며 미확인 저장 표기는 근거로 사용하지 않는다. 이 출력 변환은 이번 Python의 명시적 인코딩 처리이며 과거 ASP의 디코더를 발견했다는 의미가 아니다.

## 남아 있는 원본 문제

- 연간 2021~2050년의 원본은 빈 본문·별점 1·점수 0인 초기 행이다. 2027년 판정도 미작성이다.
- 새 연간·월별 표의 간 코드·성별 bit·항목·점수 축은 원본 호출 규칙이 확인되지 않았다.
- `TB_Saju_OtherUnse`는 job/jikjang/money/social만 들어 있다. 차량·휴대전화·주소 키의 원문은 없으므로 그 키의 뜻을 추측하지 않고 일반 조언만 허용한다.
- 탄생일의 `wiki_story/wiki_person`, 궁합의 `tbAisyo` 및 일부 interlife·행성·택일 판정 자료는 백업에 없다.
- 탄생석의 과거 음력 분기는 미할당 변수가 있어 그대로 활성화하지 않는다.
- 직업 등 COM 내부 계산은 테이블 복원만으로 구현되지 않는다.

자료가 부족한 계산은 `include_ai=false`로 부분 결과와 이유를 확인한다. 판정 미완성 요청의 AI 생성은 차단한다. 잘못된 입력과 미지원 연도는 기존 검증 오류를 유지하며, 존재하지 않는 자료를 정상 결과처럼 만들지 않는다.

## 검증 결과

실제 적재 후 전체 재실행에서 78개 표가 모두 `already_present`였고, 기존 만세력 전체 해시는 동일했다. 실제 API의 306개 기본 예시는 모두 HTTP 200이었으며 추가 NULL·변조·누락 자료·음력 분기·2027년 차단을 검사했다. 306건에는 자료 진단도 포함되며 모두 완성된 un을 뜻하지 않는다. 현재 해석 계약 준비 64개, 달력 계산 전용 2개, 부분 계산 110개로 Python 실행 경로는 총 176개다.

전체 회귀 1,468개·하위 검사 56개와 최종 자료 관련 86개, AI 계약 관련 57개, 인증·전송 관련 61개 검사를 통과했다. Ruff·compileall 및 48개 런타임 파일의 wheel 동일성을 검증했다. 실제 Claude에서는 평생사주 13항목과 탄생화 2항목을 확인했다. 탄생화의 최초 형식 불일치 1회도 호출 시도로 유지했으며, 이번 검증은 총 3회 호출했다. 기존 6회를 포함한 당일 사용량은 9/100이다. 자동 재시도나 사용량 환불·초기화는 하지 않았다.
